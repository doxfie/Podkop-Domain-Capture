# Podkop Domain Capture

![OpenWrt](https://img.shields.io/badge/OpenWrt-BusyBox%20ash-00B5E2)
![Dependencies](https://img.shields.io/badge/dependencies-tcpdump--mini%20%2B%20nft-orange)
![Version](https://img.shields.io/badge/version-0.3.0--beta-blue)

SSH-утилита для OpenWrt: показывает, к каким доменам обращается устройство в сети,
чтобы добавить их в Podkop.

Домены собираются из двух источников одновременно:

- **DNS** - лог запросов `dnsmasq`;
- **SNI** - имя сервера из TLS ClientHello, снятое с `br-lan`.

---

## 🚀 Установка

```sh
wget -O /usr/bin/pdc https://raw.githubusercontent.com/doxfie/Podkop-Domain-Capture/main/podkop-domain-capture.sh && chmod +x /usr/bin/pdc && pdc
```

Дальше просто `pdc`

## 🕸 Зачем SNI

`dnsmasq` видит запрос, только если клиент спросил роутер. Часто он не спрашивает:

| Ситуация | DNS-лог | SNI |
|---|---|---|
| Ответ закеширован, идёт по сохранённому IP | — | домен |
| Свой DoH (`8.8.8.8`, `1.1.1.1` по :443) | — | домен |
| Свой DoT (:853) | — | домен |
| IP зашит в прошивку | — | домен |
| Обычный запрос через роутер | домен | домен |

Имя хоста уходит открытым текстом в самом TLS-соединении, поэтому SNI виден там,
где DNS-лога нет. В списке уникальных доменов такие показываются отдельным блоком.

## 🎛 Использование

Отметьте клиента, встаньте на «Начать сбор доменов» и нажмите `Enter`.
Настраивать ничего не нужно, текущие параметры видны на том же экране:

```text
   Источник:  DNS + SNI
   Правила:   перехват DNS, блок DoT, блок QUIC

Клиенты
   [ ] Все клиенты
   [x] 192.168.1.141   TCL-65C6K   68:c8:c0:b4:10:ed   10h 30m
   ...

Действия
 > Начать сбор доменов
   Настройки сбора
   Назад
```

Во время сбора **выполните на устройстве то, что хотите поймать** - откройте приложение,
нажмите проверку обновлений, запустите воспроизведение. Без этого нужного трафика
не возникнет. Сбрасывать DNS-кеш не обязательно: SNI видит домен и при закешированном
резолве.

Сбор останавливается **любой клавишей** (`Ctrl+C` тоже работает). Клавиши в меню: `↑`/`↓` - выбор, `Space` - отметить клиента,
`Enter` - подтвердить, `q` - назад.

### Временные правила

На время сбора поднимается отдельная nft-таблица `inet pdc_capture`:

- **перехват DNS** - `redirect` порта 53 клиента на роутер, ловит хардкод вроде `8.8.8.8`;
- **блок DoT** - закрывает :853;
- **блок QUIC** - закрывает udp:443, иначе ClientHello зашифрован и SNI не прочитать.

Таблица отдельная, `fw4`, `podkop` и `zapret` не задевает. Снимается сама при `Ctrl+C`
и при выходе. Если осталась: `nft delete table inet pdc_capture`.

Отключить их можно в пункте «Настройки сбора», там же выбор одного источника.

## 📝 Лог

`/tmp/podkop-domain-capture.log`, формат `HH:MM:SS IP DOMAIN SRC`, где `SRC` - `dns` или `sni`.

`dnsmasq logqueries` включается только на время сбора.

## 🔄 Обновления

При запуске, но не чаще раза в сутки, скрипт сверяет свою версию с репозиторием
и обновляет `tcpdump-mini`. Новая версия ставится и перезапускается сама.
Фонового процесса нет: не запускаете `pdc` - ничего не происходит.
Без интернета проверка пропускается.

`tcpdump` обязателен: при первом запуске ставится `tcpdump-mini` (~385 КБ), три попытки,
иначе скрипт завершается - без него SNI не работает.

Адрес обновления переопределяется через `PDC_SCRIPT_URL`.

## ⚙️ Требования

OpenWrt с BusyBox `ash` (нужна поддержка `read -s -n 1`), `awk`, `sort`, `grep`, `sed`, `wget`,
`nft`. `tcpdump-mini` ставится сам.

Проверено на OpenWrt 25.12.5 (mediatek/filogic), рядом работают Podkop 0.7.21 и zapret.

---

## ⚠️ Ограничения

- SNI не виден при **ECH** (Encrypted ClientHello).
- Очень крупный ClientHello может не поместиться в один TCP-сегмент - такой домен пропускается.
- В режиме «все клиенты» трафик самого роутера исключается по IP.
