# Podkop Domain Capture

![OpenWrt](https://img.shields.io/badge/OpenWrt-BusyBox%20ash-00B5E2)
![Dependencies](https://img.shields.io/badge/dependencies-tcpdump--mini%20%2B%20nft-orange)
![Version](https://img.shields.io/badge/version-0.4.1--beta-blue)

SSH-утилита для OpenWrt: показывает, к каким доменам обращается устройство в сети,
чтобы добавить их в Podkop.

Домены собираются из двух источников одновременно:

- **DNS** - лог запросов `dnsmasq`;
- **SNI** - имя сервера из TLS ClientHello, снятое с `br-lan`.

---

## 🚀 Установка

```sh
wget -O /usr/bin/.pdc.new https://raw.githubusercontent.com/doxfie/Podkop-Domain-Capture/main/podkop-domain-capture.sh && tail -n1 /usr/bin/.pdc.new | grep -qx '# PDC-EOF' && chmod +x /usr/bin/.pdc.new && mv /usr/bin/.pdc.new /usr/bin/pdc && pdc
```

Дальше просто `pdc`

Скачивается во временный файл рядом и переименовывается: при обрыве связи
рабочая установка останется нетронутой, а не превратится в обрезанный файл.
Последняя строка скрипта — маркер `# PDC-EOF`: если закачка оборвалась,
его не будет и подмены не произойдёт.

## 🕸 Зачем SNI

`dnsmasq` видит запрос, только если клиент спросил роутер. Часто он не спрашивает:

| Ситуация | DNS-лог | SNI |
|---|---|---|
| Ответ закеширован, идёт по сохранённому IP | — | домен |
| Свой DoH (`8.8.8.8`, `1.1.1.1` по :443) | — | домен |
| Свой DoT (:853) | — | домен |
| IP зашит в прошивку | — | домен |
| Обычный запрос через роутер | домен | домен |

Имя хоста уходит открытым текстом в самом TLS-соединении, поэтому SNI виден там,
где DNS-лога нет. В логе у каждой строки указан источник, так что видно, какие домены
пришли только по SNI.

## 🎛 Использование

Отметьте клиента, встаньте на «Начать сбор доменов» и нажмите `Enter`.
Настраивать ничего не нужно, текущие параметры видны на том же экране:

```text
   Источник:  DNS + SNI
   Правила:   перехват DNS, блок DoT, блок QUIC

Клиенты
   [ ] Все клиенты
   [x] 192.168.1.141   TCL-65C6K   68:c8:c0:b4:10:ed   10h 30m
   ...

Действия
 > Начать сбор доменов
   Настройки сбора
   Назад
```

Во время сбора **выполните на устройстве то, что хотите поймать** - откройте приложение,
нажмите проверку обновлений, запустите воспроизведение. Без этого нужного трафика
не возникнет. Сбрасывать DNS-кеш не обязательно: SNI видит домен и при закешированном
резолве.

Сбор останавливается **любой клавишей** (`Ctrl+C` тоже работает). Клавиши в меню: `↑`/`↓` - выбор, `Space` - отметить клиента,
`Enter` - подтвердить, `q` - назад.

### Временные правила

На время сбора поднимается отдельная nft-таблица `inet pdc_capture`:

- **перехват DNS** - `redirect` порта 53 клиента на роутер, ловит хардкод вроде `8.8.8.8`;
- **блок DoT** - закрывает :853;
- **блок QUIC** - закрывает udp:443, иначе ClientHello зашифрован и SNI не прочитать.

Таблица отдельная, `fw4`, `podkop` и `zapret` не задевает. Снимается сама при `Ctrl+C`
и при выходе. Если осталась: `nft delete table inet pdc_capture`.

Отключить их можно в пункте «Настройки сбора», там же выбор одного источника.

## 📝 Лог

`/tmp/podkop-domain-capture.log`, формат `HH:MM:SS IP DOMAIN SRC`, где `SRC` - `dns` или `sni`.

`dnsmasq logqueries` включается только на время сбора.

## 🔄 Обновления

При запуске, но не чаще раза в сутки, скрипт сверяется с **последним релизом**
на GitHub и обновляет `tcpdump-mini`. Новая версия ставится и перезапускается сама.
Фонового процесса нет: не запускаете `pdc` - ничего не происходит.
Без интернета проверка пропускается.

Обновление идёт по тегу релиза, а не по ветке `main`: в ветку попадает и работа
в процессе, а тег - это осознанный выпуск. Команда установки выше берёт файл из `main`,
поэтому свежая установка может оказаться новее последнего релиза - тогда обновлений
просто не будет, откат на старую версию не делается.

Файл подменяется переименованием, а не перезаписью: работающий шелл дочитывает
свой прежний файл, иначе он поймал бы обрывок новой версии на середине.

Модель доверия простая: HTTPS до GitHub с проверкой сертификата (нужны
`libustream-mbedtls` и `ca-bundle`, обычно уже стоят). Подписи нет - кто может
изменить файл в репозитории, тот меняет и то, что вы получите.

`tcpdump` обязателен: при первом запуске ставится `tcpdump-mini` (~385 КБ), три попытки,
иначе скрипт завершается - без него SNI не работает.

Источник обновления переопределяется:

```sh
PDC_SCRIPT_REPO=fork/Podkop-Domain-Capture pdc   # другой репозиторий, тоже по релизам
PDC_SCRIPT_URL=https://example.com/pdc.sh pdc    # конкретный файл, минуя релизы
```

Если `tcpdump-mini` не поставить в принципе - например, релиз OpenWrt уехал в архив
и фид отдаёт 404, - можно запуститься без него:

```sh
PDC_SOURCE=dns pdc
```

Умолчание это не меняет: без переменной отсутствие `tcpdump` по-прежнему
останавливает запуск, чтобы сбор молча не деградировал до неполного списка.
Без SNI в него не попадут домены с закешированным ответом, клиенты со своим
DoH/DoT и с зашитым в прошивку IP.

## ⚙️ Требования

OpenWrt с BusyBox `ash` (нужна поддержка `read -s -n 1`), `awk`, `sort`, `grep`, `sed`, `wget`,
`nft`. `tcpdump-mini` ставится сам.

Проверено на OpenWrt 25.12.5 (mediatek/filogic), рядом работают Podkop 0.7.21 и zapret.

## 🌐 IPv6

Учитывается наравне с IPv4: устройства предпочитают IPv6, когда он есть, и без этого
часть доменов просто не попадала бы в список.

Клиент отбирается **по MAC**, а не по адресу. Одно правило покрывает у него обе версии
протокола и все временные адреса, которые privacy extensions плодят десятками и меняют
на ходу. MAC берётся из `/tmp/dhcp.leases` по выбранному IPv4; если его там нет, отбор
откатывается на адреса.

Фильтр DNS-лога - единственное место, где нужны именно адреса: в логе `dnsmasq` есть
только IP клиента. Список его IPv6 собирается из таблицы соседей (`ip -6 neigh`), она
покрывает и SLAAC, и приватные адреса. Адрес, созданный устройством уже во время сбора,
в этот список не попадёт, но домен всё равно будет пойман по SNI - там отбор идёт по MAC.

## ⚠️ Ограничения

- SNI не виден при **ECH** (Encrypted ClientHello).
- Очень крупный ClientHello может не поместиться в один TCP-сегмент - такой домен пропускается.
- IPv6-пакеты с extension headers не разбираются: ожидается TCP сразу за основным заголовком.
- В режиме «все клиенты» исключаются собственные адреса роутера.
